# Current live-only route gate — 14 October 2026

This is a release check, **not** a proposal to publish 31 stale promotions. A fresh read-only run of `node scripts/audit-live-only-priority-candidates.mjs` still found the same 31 live-published posts missing exact local assets: 13 racing-tip/extra-place hybrids and 18 offer-news stories. Every one contains `/go/` links, offer mechanics and odds/price claims; 30 use current-day language. No safe automatic non-commercial subset exists. The one without current-day wording is an offer-led story. Creating title-only pages would conceal this gap, not migrate the content.

## Per-route acceptance before adding a preview

1. Fetch the **current** public WordPress REST record by numeric ID and record `id`, `status`, exact `link`, `slug`, published/modified timestamps, title, SEO title/description/robots/canonical and a SHA-256 of the rendered body. Reject a changed ID, non-published status or a path other than `/<slug>.html`. Refresh the snapshot if the modified timestamp changes.
2. Retain the article's substantial dated editorial content, including a complete validated table when the source has one. Merely stripping links and most copy is not a faithful route. Transform present-tense statements individually into clearly historical descriptions; label the event date prominently. Keep tip/odds figures only as **historical records**, never as current selections or current prices. Review each bookmaker's claimed historical terms before retaining them; otherwise omit the claim with an explicit editorial note, not a silent gap.
3. Remove `/go/` and other affiliate destinations, live-signup buttons, current-offer cards, newsletter hooks and structured data implying an available promotion. Do not manufacture approved ACF offer IDs or current terms. If a meaningful article cannot survive these removals, leave the route blocked.
4. Build the exact asset as `dist/<slug>.html`, not `dist/<slug>/index.html`, and verify the HTTP path and any trailing-slash behaviour. In preview, require a visible dated-archive banner, `noindex,nofollow`, a preview marker, no active CTA and a responsive table. Compare article text/table rows and internal editorial links against the locked source; inspect on mobile.
5. Record SEO parity separately from preview safety. The preview's intentional noindex is **not** public SEO parity. A future indexable release needs reviewed title, description, canonical and robots for that exact URL, plus source status/modified-time recheck. Historical offer pages may instead stay noindex by an explicit editorial decision; do not infer it from a preview flag.

## Domain cutover gate

Run `npm run check`, `npm run test:content`, `npm run test:routes`, an opt-in exact-route build, `node scripts/audit-launch-readiness.mjs --fresh-live`, and then `node scripts/audit-launch-readiness.mjs --strict`. `--fresh-live` is read-only and must report no unexplained new or modified live paths. A passing preview-safety run alone is insufficient: `--strict` must fail while any reviewed route is missing, noindex-only against an indexable source, or canonical-mismatched.

The owner chose a **priority launch set first**, but that does not permit 31 existing 200 URLs to become 404s. Before any full-domain route switch, each current live 200 needs either a complete reviewed Astro exact route or an independently tested WordPress-origin fallback. No such production fallback exists in the current static-only setup. The eight owner-managed legacy rewrite paths are a separate exact-route gate. Neither this check nor a count of generated preview assets authorises a deploy, DNS change or commercial CTA activation.
