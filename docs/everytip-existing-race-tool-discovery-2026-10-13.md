# Possible source for the daily tips upload — 13 October 2026

Read-only local inspection found `../ukhr-app/app.py`, a Streamlit **UK Races Processing Tool**. Its input parser already reads a race date from each race header. The runner input columns include `Tissue` at position 5, `F/C Odds Decimal` at position 4 and `Minimum BSP` at position 7. The app currently discards `Tissue`, selects one horse per race by the lowest Minimum BSP (then forecast decimal), and exports only a seven-column TSV headed `Time,Racecourse,Horse Name,FC Decimal,Jockey,Trainer,Min BSP`.

That output is **not** interchangeable with the Astro Dark Horse contract's `Time,Course,Horse Name,Forecast SP,Jockey,Trainer,Tissue Value Price`: `Min BSP` must not silently be labelled as `Tissue Value Price`. The app also does not export the selected race date, a unique upload ID, generation timestamp or CSV hash. No dated source file was found in this workspace, and there is no evidence that the app's one-horse-per-race algorithm is the same as the live Dark Horse selection rule.

Before adapting this tool, confirm that it is the daily workflow Eric actually uses for the Dark Horse and Kempton Ninja table `72501`, and confirm whether the live table uses this app's one-per-race selection or a different value-bet filter. If confirmed, add a **separate**, explicitly named export for the Astro seven-column feed using the source Tissue field and race date, plus the existing manifest contract; retain the current TSV export unchanged. A SHA-256 manifest provides byte-integrity and a unique upload ID provides replay protection in the local importer; neither authenticates the operator or proves the racing data is correct. Do not publish an export without editorial validation of its rows and date.
