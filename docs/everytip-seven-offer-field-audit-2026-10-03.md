# Seven-offer field inventory (local/read-only)

Run `node --env-file=.env.local scripts/audit-staging-offer-fields.mjs` from `et-astro`. The script only GETs the seven known staging offer IDs through the capability-checked editorial REST route. It refuses another host and emits presence flags, dates and status, not the offer copy, full-terms text, official URL, or affiliate destination. It changes no WordPress record and cannot enable CTAs.

The fields are mapped to the current WPGraphQL display query in `src/lib/offer-field-audit.mjs`. `public_headline` and `compact_terms` are the central source for sitewide headline and the owner's approved space-restricted disclosure; article blocks store only a central offer ID. Separately entered `full_terms` or a direct official HTTPS `et_offer_full_terms_url` are optional enhancements, not mechanical prerequisites for displaying that central short copy. Optional highlight and bookmaker USPs are separate editorial copy, never substitutes for terms. This records the owner's editorial policy, not a legal-compliance finding.

`missingRequired` is a mechanical content inventory, not publication approval. The 30-day `last_checked` review indicator is a work-queue suggestion, not a regulatory threshold or proof of validity. The script does not verify claims, operator terms, country eligibility, destination, the private source URL/checked-by fields, or the seven offers' current GraphQL visibility. WPGraphQL's public query may omit WordPress drafts; use the authenticated REST inventory to inspect them. The offer renderer remains fail-closed and preview CTAs remain disabled.

On 3 October 2026, the first staging audit attempt timed out connecting to Cloudways before retrieving an offer, so current field-by-field completeness could not be asserted from this run. Retry the read-only command when staging is reachable. Unit and contract tests are in `tests/offer-field-audit.test.mjs`.
