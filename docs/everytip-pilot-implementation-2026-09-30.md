# EveryTip migration pilot — implementation status

## Design decision — 2 October 2026

The owner accepted the restrained blue/orange facelift across the local pilot. `design-refresh.css` is now applied unconditionally by the pilot layouts; the `?design=` comparison toggle has been removed. The five representative routes remain linked from `/pilot/design-review/`, now an approved-design index. This locks the visual direction for WordPress content integration, not a production launch or approval of unverified offer copy.

Date: 30 September 2026. Scope: cloned/staging WordPress application `2098144` and local `et-astro` only. No live WordPress content, DNS, Cloudflare deployment, affiliate link, or tip import changed.

## Staging ACF model saved

- Custom post types `et_offer` and `et_bookmaker`: public, REST enabled, revisions enabled, exposed through WPGraphQL. GraphQL root collections are `everytipOffers` and `everytipBookmakers`.
- `EveryTip Offer Details (Pilot)` field group (ID 90821): `offer_type`, `public_headline`, `full_terms`, `compact_terms`, `affiliate_url`, `bookmaker` (post object restricted to `et_bookmaker`). The reusable offer record is intended to supply all placements, including cards and compact/full terms.
- `EveryTip Bookmaker Details (Pilot)` field group (ID 90828): `logo`, `review_url`.
- `EveryTip Roundup Guide (Pilot)` field group (ID 90831): `guide_intro` and ordered `ranked_entries` repeater. Each row has an `offer` relationship, `best_for`, and `editorial_verdict`. The WordPress editing UI is currently limited to posts in the Betting Guides category. The field group is manually mapped to GraphQL `Post` and `Page` types so the API can read it on either type; page editing location rules still need refining for the cash-out pilot.

Public WPGraphQL smoke tests succeeded for `everytipOffers`/`everytipBookmakers`, the offer headline/terms/URL fields, and `everyTipRoundupGuide { guideIntro rankedEntries { bestFor editorialVerdict } }` on posts. Collections are empty because no offer/bookmaker test records were published. Public schema introspection is disabled by the existing WPGraphQL settings, so smoke tests used ordinary queries. No setting was weakened to enable introspection.

**Schema issue to fix before integration:** ACF persisted the Select field `offer_type` with GraphQL field name `offerTypeofferType` even after editing the UI to `offerType`. A query using the doubled name succeeds, but it is not the intended API contract. Do not ship a frontend query against that accidental name; correct and re-test the field configuration first.
